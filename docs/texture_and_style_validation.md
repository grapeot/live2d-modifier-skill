# 贴图缩放、原生发型扩展与交付验收

## 1. 透明贴图缩放

使用 `l2d-mod resize` 对超限 PNG 贴图进行降采样：

```bash
l2d-mod resize /path/to/model work/resized --max-size 4096
l2d-mod moc check work/resized
l2d-mod sheet work/resized -o work/resized_sheet.png
l2d-mod motion work/resized -o work/resized_frames --frames 48 --fps 12
# 读图并完成下述近景检查后，再打包、安装
l2d-mod package work/resized -o work/delivery.zip
l2d-mod vts work/resized --name "ResizedModelVariant"
```

### 行为与约束

- **目录与复制范围**：目标必须为全新目录且与源不重叠。命令仅读取源目录，解引用软链接，在目标复制模型引用的资源、根目录表达式和 VTS 配置；不复制未被引用的笔记与 captures。
- **尺寸与格式策略**：仅将超过上限的 PNG 页按原比例缩小，最长边不超过上限，最短边至少 1 像素；不放大小页，未超限页面逐字节保留。拒绝需要缩放的非 PNG 贴图。moc、UV、模型引用和 VTS 身份保持不变。
- **缩放算法**：采用 float32 预乘 alpha，对 alpha 与预乘 RGB 各通道分别执行 Lanczos 过滤后再除回 alpha，避免 8-bit 预乘还原精度损失导致低 alpha 叠层出现色差接缝。该过程是 encoded-RGB 过滤，并非 linear-light 过滤；不保证消除原有瑕疵或所有采样误差。
- **本地审计清单**：`texture_resize_manifest.json` 记录源路径、页面尺寸和 SHA256。此文件含本地路径，不打进 `package`，不随模型上传。

### 视觉验收步骤

1. `resize` 不运行浏览器或 Cubism Core，不自动完成视觉验收，必须执行后续验证。
2. 缩图前后在同参数、同视角下检查嘴周、胸口、配饰边缘等近景；全身小图不算细节验收。保留前后对比图与固定 ROI。
3. 发现异常时先复现问题，修复后再按同条件复检。因分辨率已变，不承诺与高分辨率原图逐像素相同；仅对本应不变且条件一致的区域使用精确比对。

## 2. 原生发型扩展

发型原生参数开关不等于最终网格可见，需区分参数关闭与关键帧 alpha 清零（硬隐藏）。

1. **核验硬隐藏**：仅基于同源模型、经过核验的网格及关键帧映射考虑恢复。遇到未知二进制布局停止猜测，转入独立结构实验；本工具没有通用恢复 CLI。
2. **跨部件核对**：部件名称可能不能完整描述归属，例如镜像发丝可能挂在饰品部件下。结合 inventory、网格、贴图和实际渲染核对选区。
3. **重检默认值**：解除硬隐藏后检查默认加载外观，防止原本被硬隐藏遮住的开启参数突然显现。
4. **记录完整参数组**：正常发型避免同时打开多个互斥后发家族；左右辫、鬓发等装饰轴可独立配置。排除不适用开关、重复状态和不打算使用的叠层；测试覆盖指已验收的命名组合，不声称穷举全部参数交叉。
5. **表达式配置**：旧 `Add` 表达式存在叠加风险，可为互斥发型定义完整 `Overwrite` 参数组。但同时激活多个 `Overwrite` 仍可能冲突，需要在 VTS 中实测切换、撤销后的默认状态。这是配方建议，不是新增表达式生成命令。

## 3. 镜像共享 UV 的渐变约束

左右镜像共享 UV 的网格不能在同一纹理像素上同时拥有不同的世界空间左右颜色。

1. 着色前先确认目标网格是否共享 UV。
2. 共享时选择根到梢进度等镜像兼容坐标，或明确拆页（`split`）。根梢映射是具体配方需验证的策略，不是新增 CLI 功能。
3. 在共享页上写入互相矛盾的左右渐变可能只保留局部颜色。验收时检查所有目标色段是否真正可见，不能仅确认贴图已染色。

## 4. 原生特征和新增瑕疵的区分

发现看似串珠或裂缝的异常时，先在同参数下对照原件，再比较相关顶点、网格 opacity 与贴图 alpha。属于原生设计的特征不当作新增缺陷修补。

`moc check` 不等于视觉验收或真实摄像头验证。连续动作检查必须包含实际转头，不得仅凭静止帧宣布通过。记录所测姿态和参数范围，采样结果不等于穷举保证。

## 5. 交付闭环与并行交接

1. **锁定候选目录**：指定唯一候选版本作为验证与打包源。
2. **结构与视觉验收**：完成结构检查及声明范围内的动作、近景验收。
3. **打包校验**：`package` 打包引用资源及根目录表达式/VTS 配置，排除缩图清单。主动检查 ZIP CRC、资源引用完整性、解包内容哈希和贴图尺寸。
4. **安装身份**：`resize` 保留原 ID，`vts` 安装分配新名称和新 ID。保留原件；原地更新已有安装需明确授权和备份。
5. **安装后核验**：安装成功不等于审计完成。主动读取实际安装文件的哈希并重新渲染；离线渲染不代表验证了 VTS 摄像头追踪或真实热键行为。

后台交接应包含固定版本目录、就绪状态、准确测试范围、已知限制/不通过项和哈希清单。并行任务各用独立目录，不读取或修改仍在生成的共享产物。冻结候选后，以同一版本执行合并、打包和安装；晚到的新版本需重新验收，不默默替换。只合并负责范围内的增量，例如发型页和网格映射，避免覆盖另一任务的配饰。
