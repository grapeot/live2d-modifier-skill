# 产品需求文档（PRD）：live2d-modifier-skill

## 1. 项目背景与定位

Live2D 创作者与虚拟主播在调整现有模型外观（换装配色、增加空间渐变、改换表面纹样或妆容）时，通常面临两难：简单的色相偏移（Hue Shift / Multiply Tint）只能做全部件均匀变色，无法表达空间渐变与局部花纹；而重画 PSD 并重新在 Cubism Editor 中绑骨耗时漫长，且当手里只有导出的 `.moc3` 运行时模型而无 `.cmo3` 源文件时无法走通。

`live2d-modifier-skill`（CLI 名称 `l2d-mod`，Python 包名 `live2d_modifier`）提供一条非破坏式的模型外观改款管线：从合法取得、已经绑定的 Live2D Cubism 模型出发，根据风格描述或参考图，利用高分辨率渲染采集、外部图像编辑、部件级色彩拟合与 UV 残差回投生成新外观，完整保留原模型的动作绑定。

相关核心技术已从私有原型整理为公开 GitHub 项目与根 Agent Skill。公开版已通过离线测试、软件打包检查和独立 Agent 的真实模型新风格改款验收，模型与测试素材留在外部私有工作目录。

## 2. 目标用户与使用方式

1. **AI 编程助手用户**：将本仓库 GitHub URL 交给 Claude Code、Codex、Cursor 或 OpenCode 安装根 Skill（`skills/live2d-modifier/SKILL.md`），由 Agent 串联盘点、采集、重绘、回投与多姿态检验全流程。
2. **技术创作者与工具开发者**：直接通过 `l2d-mod` CLI 对自有模型做结构盘点、贴图冲突拆页、确定性像素修补、动作联系表渲染及 VTube Studio 导入。

## 3. 功能范围

### 3.1 纳入范围（In Scope）

- **13 个已验证 CLI 命令**：`inventory`、`render`、`sheet`、`capture`、`pick`、`conflicts`、`transfer`、`variant`、`texels`、`page`、`moc check`、`vts`、`serve`。
- **原位模型变体操作（`variant`）**：保留参数默认值修改、`hide`/`unmask`/`blend` 部件显隐与混合控制、`affine`/`tint` 几何与基础染色、`texture`/`split` 贴图替换与冲突拆页等通用已验证能力；Skill 工作流默认只调用完成外观改款所需的操作子集。
- **图像编辑器解耦**：`capture` 输出标准 PNG 渲染图，外部图像编辑器只需看渲染图并保持原姿势、轮廓与几何线稿即可。项目不绑定特定付费图像 API，重绘结果可由 Agent 已有的生图 Skill 或人工提供。
- **跨网格撕裂防护与动作验证**：支持 `front`、`blink`、`talk`、`smile`、`turn_l`、`turn_r`、`look_up`、`sway` 多姿态检验，提供 `overrides` 与 `residual_holes` 机制处理透明/正片叠底/镜像贴图及跨网格裂纹。

### 3.2 不纳入范围（Out of Scope）

- 不包含 Umamo 新增网格或 `.cmo3` 工程往返能力。
- 不包含从零拆层、自动生成 PSD 或自动绑骨。
- 不包含任意骨架拓扑手术。
- 不为理论风险堆叠复杂权限框架或专有沙箱状态机。
- 不在仓库或发布包中打包 Live2D Cubism Core 专有文件或任何模型素材。

## 4. 标准用户旅程（7 步工作流）

1. **只读盘点**：输入原模型目录、参考图或风格要求及输出目录，运行 `inventory`、`render`、`sheet`、`pick` 摸清部件与参数，原模型目录不做任何写入。
2. **开关调整与冲突拆页**：按需用 `variant` 调整模型原生参数开关、隐藏冗余部件；复用已有配饰槽位时保留原绑定；用 `conflicts` 查找共享纹理冲突（如署名网格与待重绘衣服共用贴图），通过 `variant` / `page` 拆分到独立贴图页。
3. **高分辨率采集与外部重绘**：运行 `capture` 获取全身与头部近景高分辨率渲染图及屏幕到纹理映射；调用外部生图工具或由人工在保持姿势、轮廓、几何线稿的前提下重绘图像。
4. **色彩映射与残差回投**：运行 `transfer`，按部件拟合明暗颜色映射以保证遮挡部分底色一致，再将空间渐变、印花与妆容残差通过 UV 回投到贴图；多视角近景优先加权，透明、乘法混合与镜像共享贴图通过 `overrides` 控制。
5. **像素级确定性微调**：运行 `texels` 修补局部贴图瑕疵或边界。
6. **多姿态与运动验证**：运行 `sheet`、`render`、`moc check`、`serve` 检查 `front`、`blink`、`talk`、`smile`、`turn_l`、`turn_r`、`look_up`、`sway` 下的近景与运动表现；若跨独立运动网格的小装饰出现撕裂，配置 `residual_holes` 排除残差并恢复基础着色。
7. **独立导出与安装**：在独立新目录输出完整可用模型；运行 `vts` 时生成新模型名与新 `ModelID` 安装到 VTube Studio，不覆盖原模型。Agent 可将用户自己的改款模型打包交付给用户。

## 5. 合规、隐私与事实边界

- **零私有资产入库**：模型文件、贴图、渲染截图、真实模型部件 ID、具体角色改款配方、本机私有绝对路径均不得进入仓库；文档与示例统一使用 `/path/to/model`、`work/`、`PartExample`、`ArtMeshExample` 等虚构标识。
- **许可分离**：核心自有代码以 MIT 许可公开，公开通用算法实现，不因素材版权而隐藏通用数学与图形算法；Live2D Cubism Core 由使用者按原厂许可自行提供。
- **期望管理**：明确区分已确认的私有原型实验成功与公开版待验收状态；如实说明不同模型结构差异带来的调参需求，不承诺对所有模型全自动一次成功。

## 6. 公开版验收标准

1. **公开 CI 测试（无模型）**：仅使用代码生成的 synthetic 数学与贴图 fixture，验证色彩拟合、UV 回投、冲突拆页、像素微调与配置解析逻辑，全程禁用外部模型与付费 API。
2. **外部私有真实模型 E2E 验收**：在仓库外的私有工作目录中，由独立 Agent 按照 `SKILL.md` 对真实模型执行新风格改款，逐项核对加载正常、8 组标准动作无撕裂、原模型未改动且新模型完整、视觉质量达标以及管线可重放。
